# Database

PostgreSQL 16 with `pgvector` and `citext`. Schema lives in SQLAlchemy models
(`apps/backend/src/mirra/modules/*/models.py`) and Alembic migrations
(`apps/backend/migrations/versions`). The initial migration creates all 20 tables; the test suite
rebuilds the schema from migrations on every run, and CI checks `upgrade → downgrade → upgrade` and
that the models match (`alembic check`).

## Conventions

- UUID primary keys generated by Postgres (`gen_random_uuid()`), except `marketplaces.id` (a slug
  such as `ebay`) and `price_history.id` (bigint).
- `created_at` / `updated_at` are `timestamptz`.
- Enums are stored as `VARCHAR(32)`. Stable enums have a CHECK constraint (condition, authenticity,
  availability, fidelity…). The fast-moving taxonomy (`category`, `body_region`) is validated in the
  API layer only, so adding a category doesn't need a migration.
- Money is `NUMERIC(12,2)` plus an ISO-4217 currency. `NULL` means unknown; `0` means free. The two
  are never conflated.
- Constraint names follow the naming convention in `db/base.py`, so migrations are deterministic.

## Tables

| Table | Purpose | Notes |
|---|---|---|
| `users` | Accounts | `email` is `citext` (case-insensitive unique). Argon2id password hashes. |
| `auth_sessions` | One row per refresh token | SHA-256 of the token, `family_id`, `client` (web/desktop), `revoked_at`, `replaced_by_id`. |
| `user_preferences` | Style profile | Styles, brands, colours, sizes (JSON), budget, currency, ship-to country, render quality. 1:1 with users. |
| `avatars` | Saved avatar configs | Normalized body params (JSON, 0..1) + appearance; `rig_version`; partial unique index → one default per user. |
| `products` | Normalized products | Brand, category, colours, attributes (JSONB, GIN), GTIN/MPN/style code, `canonical_key` for merging, generated `search_vector` (GIN). |
| `product_images` | Images per product | Optionally linked to the listing they came from. |
| `product_embeddings` | Image/text embeddings | `vector(768)`, HNSW cosine index, unique per (product, image, model, kind). |
| `marketplaces` | Known marketplaces | Slug PK, integration type, status, capabilities. |
| `sellers` | Marketplace sellers | Unique per (marketplace, external id); feedback score/percent. |
| `marketplace_listings` | A product on a marketplace | Own seller, price, shipping, condition, authenticity, availability, sizes, reviews, original URL, `fetched_at`/`expires_at`. Unique per (marketplace, external id). `product_id` nullable until matched. |
| `price_history` | Price observations per listing | Indexed by (listing, observed_at). |
| `garment_assets` | 3D garments | Slug, category, body region, layer, fidelity, GLB path **or** parametric spec (CHECK), rig/asset version, materials, colour variants. `exact` requires `product_id` (CHECK). |
| `garment_compatibility` | Pairwise garment rules | `conflicts` / `requires` / `hides`. |
| `wardrobe_items` | Clothes a user owns | Optional links to product, listing, garment asset, upload. |
| `outfits` | Saved outfits | Source (manual / AI), rationale, total of *known* prices + `price_complete`, share slug. |
| `outfit_items` | Pieces of an outfit | Body region + layer; must reference at least one of wardrobe item / product / listing / garment (CHECK). |
| `saved_products` | Bookmarked products/listings | Unique per user + target (`NULLS NOT DISTINCT`). |
| `search_history` | Searches | Query type, text, upload, filters, parsed structured query, result count. |
| `shopping_events` | Views, click-outs, reported purchases | Feeds the Shopping History page. |
| `uploads` | User images in private object storage | SHA-256, size, purpose. Deleting the row deletes the object. |

## Relationships

```
users ─┬─ user_preferences (1:1)
       ├─ auth_sessions
       ├─ avatars
       ├─ wardrobe_items ─┬─ products? ─ listings? ─ garment_assets? ─ uploads?
       ├─ outfits ─ outfit_items ─┘
       ├─ saved_products, search_history, shopping_events, uploads

products ─┬─ product_images ─ product_embeddings
          ├─ marketplace_listings ─┬─ marketplaces
          │                         ├─ sellers
          │                         └─ price_history
          └─ garment_assets (exact fidelity)
```

Deleting a user cascades to everything they own. Deleting a product nulls out references from
listings, wardrobe items and outfits rather than deleting user data.
